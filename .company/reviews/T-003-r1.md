## Root cause of run 39529331526 ("cannot pull with rebase: You have unstaged changes")
The run used runner image `ubuntu-26.04`, whose `python3` is 3.14. Commit 1e6bde5 (T-002) **tracks compiled bytecode**:
`scripts/__pycache__/generate.cpython-314.pyc` and `scripts/__pycache__/test_generate.cpython-314.pyc`.
`.gitignore` contains only `.company/runs/`. After checkout, source mtimes no longer match the mtime in the pyc header,
so the "Test generator" step rewrote both tracked `.pyc` files. Those are modified tracked files outside `assets/generated`.
The step committed only `assets/generated` (2 files), and `git pull --rebase` then refused because of the dirty `.pyc` files.
(Untracked files would not block a rebase; modified tracked files do. That is why the error names "unstaged" changes.)

The addendum fix does work around it. `PYTHONDONTWRITEBYTECODE: 1` stops the rewrite, and `--autostash` would cover
any remaining dirt. But the actual cause, bytecode committed to git, is still in the repo. Any local test run on
Python 3.14 dirties the tree again, and the next `git add -A` or `git commit -a` would push fresh binaries to the public profile repo.
