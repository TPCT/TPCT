## Focus-area findings
- Counting: `contributions_last_year` uses `contributionCalendar.totalContributions` only, and `restrictedContributionsCount` is
  not added (the fetch test even supplies it and asserts 8667). Stars and languages are summed once per repo node across pages.
  `public_repos` = `totalCount` with `isFork: false, privacy: PUBLIC, ownerAffiliations: OWNER`, so forks are excluded from
  repos, stars and languages, as intended. The real run gives 8,669 contributions, which is consistent with the 8,667 measured
  earlier, so there is no double counting.
- Escaping: every dynamic string (titles, names, descriptions, language names, API colors) goes through `html.escape(quote=True)`.
  The test covers `&`, `<` and `"`.
- Workflow safety: `contents: write` only, a single job, so it is minimal. No loop: generated commits touch only
  `assets/generated/**` (outside the push `paths`), and the push uses the checkout-persisted GITHUB_TOKEN, which does not
  trigger workflows (true even when PROFILE_TOKEN is set, because that is only passed as env to the generate step). `concurrency`
  is set without cancel-in-progress, and there is a 10-minute timeout. Tests run before generation.
- Token in Actions without contribution access: a GraphQL `errors` response or HTTP 4xx leads to RuntimeError, exit 1, no files
  written, the job fails and nothing is committed. This fails loudly rather than writing zeros, as in architecture "Risks".
  The remaining risk is a token that silently returns a lower calendar total. The PROFILE_TOKEN fallback covers that, and it should be checked after the first scheduled run.
- Token hygiene: the token is used only in the Authorization header. Error messages contain only status codes or generic text.
- Determinism: fixed dict and FEATURED order, language sort (size desc, name), fixed float formats, `\n` newlines, no timestamps
  or ids. Re-runs are byte-identical (verified). Dark and light differ only in colors (verified by diffing with colors stripped).
